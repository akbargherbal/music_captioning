# `yt_top_500` — SheetSage2 transcription runbook

Operational guide for the 495-track `yt_top_500_music_playlist` corpus. The
design and guardrail rationale is in the `arabmaqamrock` repo:
`docs/plans/yt-top-500-transcription.md`.

**Corpus:** `gs://akbar-december-2024-backup/yt_top_500_music_playlist`
**Audio:** 495 `.m4a`, 38.27 h, 2.08 GiB, all `done`
**Manifest:** `outputs/YT500/manifest.jsonl`
**Shards:** 25 (5 × 19 tracks, 20 × 20 tracks)
**Duplicates:** 5 same-artist/same-title groups; all 495 are transcribed,
`duplicate_of` is metadata only.

The frozen manifest hash is in `outputs/YT500/manifest.sha256`. Do not edit the
manifest; a changed corpus is a new `VER` and a new manifest.

## 1. Environment

On the L4/T4 VM:

```bash
git clone https://github.com/akbargherbal/arabmaqamrock.git /content/arabmaqamrock
git clone https://github.com/akbargherbal/music_captioning.git /content/music_captioning

cd /content/arabmaqamrock
./plumbing/setup_transcribe.sh --cuda --warm      # ~2.8 GB model, Python 3.11
sudo apt-get update && sudo apt-get install -y abcmidi
./transcribe.sh --doctor
nvidia-smi --query-gpu=name,memory.total --format=csv,noheader
df -h /content /tmp
```

Expected doctor: Python 3.11, torch `2.8.0+cu126`, transformers `4.45.2`,
`cuda: True`, exit 0.

`abcmidi` is mandatory: without it every QC row is `parse_fail`.

Auth:

```bash
gcloud storage ls gs://akbar-december-2024-backup/yt_top_500_music_playlist/state/latest/manifest.json
```

## 2. Frozen manifest

Generate once (CPU only, reads the bucket manifest):

```bash
cd /content/music_captioning
python3 scripts/yt500_manifest.py \
  --bucket gs://akbar-december-2024-backup/yt_top_500_music_playlist \
  --out outputs/YT500/manifest.jsonl --version 2026-11-09

python3 scripts/yt500_manifest.py --check outputs/YT500/manifest.jsonl
```

Expected: 495 tracks, 38.27 h, 2,228,785,610 bytes, 25 shards, 5 duplicate
groups. The command also writes `duplicates.json`, `shards.json`,
`pilot.json`, and `manifest.sha256`.

If `outputs/YT500/` came from git, just verify it:

```bash
sha256sum -c outputs/YT500/manifest.sha256
python3 scripts/yt500_manifest.py --check outputs/YT500/manifest.jsonl
```

## 3. Pilot — 10 tracks

The frozen `pilot.json` deliberately includes the shortest/median/p95/max
durations, both *Ana Blayak* versions, the live *Yhizak Al Shooq*, a Tier 3
track, an Elissa track, a short track and a `video_id` with `_`.

```bash
cd /content/music_captioning
python3 scripts/yt500_manifest.py --download-pilot \
  outputs/YT500/pilot.json --pilot-dir work/yt500/pilot

cd /content/arabmaqamrock
./transcribe.sh /content/music_captioning/work/yt500/pilot \
  --full --device cuda \
  --out-dir /content/music_captioning/work/yt500/pilot_out \
  --fail-fast
```

Gate:

- 10/10 `meta.json.status == ok`
- 10/10 `score.abc` parses (`abc2midi` exit 0)
- ≥9/10 coverage ≥ 0.80
- no `voice_missing` on a sung track
- `has_chords` true
- peak VRAM < 11 GB (T4) / < 20 GB (L4/A100)
- RTF ≥ 4× (L4/A100) or ≥ 2.5× (T4)
- the two *Ana Blayak* tracks produce two independent `ok` outputs

If the gate fails, do not start the bulk.

## 4. Bulk run

`--no-commit --gcs-index` makes GCS the durable index, so a fresh VM does not
need git push access. The driver hard-codes `--full`.

```bash
cd /content/music_captioning
export BUCKET=gs://akbar-december-2024-backup/yt_top_500_music_playlist
export VER=2026-11-09
export MANIFEST=outputs/YT500/manifest.jsonl
export MANIFEST_SHA=$(cut -d' ' -f1 outputs/YT500/manifest.sha256)

setsid nohup python3 -u scripts/abc_batch.py \
  --manifest "$MANIFEST" \
  --manifest-sha256 "$MANIFEST_SHA" \
  --index outputs/YT500/abc_index.json \
  --gcs-index --no-commit \
  --gcs-transcripts "$BUCKET/transcripts/$VER" \
  --device cuda \
  --on-collision error \
  --per-track-timeout 1800 \
  --archive-every-track \
  --restore-from-gcs \
  --assumed-rtf 5.0 \
  --max-minutes 150 \
  --amr-dir /content/arabmaqamrock \
  --work-dir work/yt500 \
  --repo /content/music_captioning \
  > logs/yt500_$(date +%Y%m%d_%H%M).out 2>&1 < /dev/null &
disown || true
```

One shard only (replace `shard-03`):

```bash
python3 scripts/abc_batch.py ... --album shard-03
```

Check the plan without a GPU:

```bash
python3 scripts/abc_batch.py --list \
  --manifest "$MANIFEST" --manifest-sha256 "$MANIFEST_SHA" \
  --index outputs/YT500/abc_index.json --gcs-index \
  --gcs-transcripts "$BUCKET/transcripts/$VER" \
  --amr-dir /content/arabmaqamrock
```

## 5. What lands where

```
work/yt500/
  audio/YT500/<shard>/<file>.m4a
  out/YT500/<shard>/<stem>/{score.abc, meta.json, *.mid, *.lab, ...}
  archives/YT500/<shard>/<stem>.tar.gz
  logs/

outputs/YT500/
  manifest.jsonl / manifest.sha256
  duplicates.json / shards.json / pilot.json
  abc/<shard>.json
  abc_index.json

gs://…/yt_top_500_music_playlist/transcripts/<VER>/
  _manifest.jsonl
  duplicates.json
  _index.json / _index-<utc>.json
  YT500/<shard>/<stem>.tar.gz
  YT500/abc/<shard>.json
```

A track is reusable only when `meta.json.status == "ok"`, its
`source_wav_sha256` matches the current audio, and `score.abc` matches
`meta.abc_sha256`. A shard is done only after every track archive is uploaded
and size+md5 verified, the packed JSON is uploaded, and the GCS index is
updated.

## 6. Resume after a VM loss

Run the same command. The driver:

1. restores `_index.json` from GCS,
2. skips shards already `done`,
3. downloads only the pending shard's audio; every download is SHA-256-verified,
4. restores any missing local transcript from `YT500/<shard>/<stem>.tar.gz`,
5. re-transcribes only tracks that are still absent or not `ok`.

Never `rm -rf` a track directory to retry and never use `--force` in bulk. A
failed upload is a hard stop (`exit 2`); the supervisor must not restart into
the next shard.
