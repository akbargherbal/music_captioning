# `yt_top_500` — SheetSage2 transcription runbook

Operational guide for the 495-track `yt_top_500_music_playlist` corpus. The
design and guardrail rationale is in the `arabmaqamrock` repo:
`docs/plans/yt-top-500-transcription.md`.

**Corpus:** `gs://akbar-december-2024-backup/yt_top_500_music_playlist`
**Audio:** 495 `.m4a`, 38.27 h, 2.08 GiB, all `done`
**Output:** `gs://akbar-december-2024-backup/TRANSCRIPTS/YT500/`
**Manifest:** `outputs/YT500/manifest.jsonl`
**Shards:** 25 (5 × 19 tracks, 20 × 20 tracks)
**Duplicates:** 5 same-artist/same-title groups; all 495 are transcribed,
`duplicate_of` is metadata only.

The frozen manifest hash is in `outputs/YT500/manifest.sha256`. Do not edit the
manifest; a changed corpus is a new project folder and a new manifest.

## 1. Two processes, deliberately separate

| Process | Runs on | Does | Never does |
|---|---|---|---|
| `scripts/abc_batch.py --skip-backup` | GPU | download → transcribe → QC → pack locally | any GCS write, any git write |
| `scripts/yt500_backup.py --watch` | CPU/network | archive complete tracks → upload → verify → index | transcribe, touch audio inputs |

They share only the filesystem and run **in parallel**. A slow upload cannot
stall the GPU, and a GPU crash cannot lose a track that was already
transcribed. The backup worker only sees a track after `meta.json` reports
`status: ok` with a matching `abc_sha256`.

## 4. Pilot — 10 tracks

The frozen `pilot.json` deliberately includes the shortest/median/p95/max
durations, both *Ana Blayak* versions, the live *Yhizak Al Shooq*, a Tier 3
track, an Elissa track, a short track and a `video_id` with `_`.

```bash
cd /content/music_captioning
python3 scripts/yt500_manifest.py --download-pilot \
  outputs/YT500/pilot.json --pilot-dir work/yt500/pilot

cd /content/arabmaqamrock
./transcribe.sh /content/music_captioning/work/yt500/pilot \
  --full --device cuda \
  --out-dir /content/music_captioning/work/yt500/pilot_out \
  --fail-fast
```

Gate:

- 10/10 `meta.json.status == ok`
- 10/10 `score.abc` parses (`abc2midi` exit 0)
- ≥9/10 coverage ≥ 0.80
- no `voice_missing` on a sung track
- `has_chords` true
- peak VRAM < 11 GB (T4) / < 20 GB (L4/A100)
- RTF ≥ 4× (L4/A100) or ≥ 2.5× (T4)
- the two *Ana Blayak* tracks produce two independent `ok` outputs

If the gate fails, do not start the bulk.

## 5. Bulk run — two detached processes

Start the backup worker first (it waits), then the GPU process.

```bash
cd /content/music_captioning
export DEST=gs://akbar-december-2024-backup/TRANSCRIPTS/YT500
export MANIFEST=outputs/YT500/manifest.jsonl
export MANIFEST_SHA=$(cut -d' ' -f1 outputs/YT500/manifest.sha256)
export WORK=work/yt500
mkdir -p logs

# B — backup worker (CPU/network)
setsid nohup python3 -u scripts/yt500_backup.py \
  --manifest "$MANIFEST" \
  --manifest-sha256 "$MANIFEST_SHA" \
  --outputs outputs \
  --work-dir "$WORK" \
  --gcs-dest "$DEST" \
  --watch --stop-when-complete --interval 30 \
  > logs/yt500_backup_$(date +%Y%m%d_%H%M).out 2>&1 < /dev/null &
disown || true

# A — GPU transcription worker
setsid nohup python3 -u scripts/abc_batch.py \
  --manifest "$MANIFEST" \
  --manifest-sha256 "$MANIFEST_SHA" \
  --index outputs/YT500/abc_index.json \
  --gcs-index \
  --skip-backup \
  --gcs-transcripts "$DEST" \
  --device cuda \
  --on-collision error \
  --per-track-timeout 1800 \
  --restore-from-gcs \
  --assumed-rtf 5.0 \
  --max-minutes 150 \
  --amr-dir /content/arabmaqamrock \
  --work-dir "$WORK" \
  --repo /content/music_captioning \
  > logs/yt500_transcribe_$(date +%Y%m%d_%H%M).out 2>&1 < /dev/null &
disown || true
```

`--gcs-index` on the GPU process is **restore-only**. The backup worker is the
only writer to `_index.json`.

One shard only (replace `shard-03`): add `--album shard-03` to the GPU command.

Check the plan without a GPU:

```bash
python3 scripts/abc_batch.py --list \
  --manifest "$MANIFEST" --manifest-sha256 "$MANIFEST_SHA" \
  --index outputs/YT500/abc_index.json --gcs-index \
  --gcs-transcripts "$DEST" \
  --amr-dir /content/arabmaqamrock
```

## 6. What lands where

```
work/yt500/
  audio/YT500/<shard>/<file>.m4a
  out/YT500/<shard>/<stem>/{score.abc, meta.json, *.mid, *.lab, ...}
  archives/YT500/<shard>/<stem>.tar.gz
  backup/{backup.log, ledger.jsonl, abc_index.json, status.json, backup.lock}
  logs/

outputs/YT500/
  manifest.jsonl / manifest.sha256
  duplicates.json / shards.json / pilot.json
  abc/<shard>.json
  abc_index.json

gs://akbar-december-2024-backup/TRANSCRIPTS/YT500/
  _manifest.jsonl / _manifest.sha256
  duplicates.json / shards.json / pilot.json
  _index.json / _index-<utc>.json
  YT500/<shard>/<stem>.tar.gz
  YT500/abc/<shard>.json
```

A track is reusable only when `meta.json.status == "ok"`, its
`source_wav_sha256` matches the current audio, and `score.abc` matches
`meta.abc_sha256`. The backup worker records every remote object in
`work/yt500/backup/ledger.jsonl`; a second pass trusts it and uploads nothing.

## 7. Resume after a VM loss

Run the same two commands. Together they:

1. restore `_index.json` from GCS (GPU process, read-only),
2. skip shards already terminal,
3. download only the pending shard's audio; every download is SHA-256-verified,
4. restore missing local transcripts from
   `TRANSCRIPTS/YT500/YT500/<shard>/<stem>.tar.gz`,
5. re-transcribe only tracks that are still absent or not `ok`,
6. adopt already-uploaded archives whose `abc_sha256` matches, instead of
   re-uploading them.

Never `rm -rf` a track directory to retry and never use `--force` in bulk. A
failed verification is a hard stop (`exit 2`); do not restart the backup worker
blindly.

Do **not** run `--retry-failed` on a shard that is already archived. Re-packing
rewrites `generated_at`, so the packed JSON changes and the append-only backup
worker rejects it (`exit 2`). Retry before archival, or use a new packed-object
namespace as an explicit operation.
